# Подготовка к защите

## Как рассказать о проекте за 2 минуты

1. **Что это:** браузерная social deduction игра до 10 игроков. Экипаж выполняет задания, предатели устраняют и саботируют, на собраниях игроки голосуют.
2. **Архитектура:** monorepo из трёх пакетов. `shared` — общий контракт: типы, Zod-схемы, карта, физика движения. `server` — авторитетный сервер на Node.js, Express и Socket.IO. `client` — React для интерфейса и Phaser для игрового мира.
3. **Главная идея:** сервер — единственный источник правды. Клиент шлёт только намерения, сервер всё проверяет и каждому игроку отправляет только то, что тот имеет право знать.
4. **Качество:** строгий TypeScript, ESLint, Prettier, тесты на Vitest (логика, сокеты, REST, карта), CI на Ubuntu и Windows.

## Вероятные вопросы и ответы

**Почему сервер авторитетный?** Иначе игрок поменяет код в браузере и назначит себе роль или убьёт с другого конца карты. Сервер сам двигает игроков, проверяет дистанцию, перезарядку, роль и фазу игры.

**Как вы не раскрываете роли?** Метод `GameRoom.viewFor(playerId)` собирает отдельное представление для каждого игрока. Член экипажа никогда не получает список предателей. Это проверено тестом, который ищет строку `IMPOSTOR` в JSON, отправленном экипажу.

**Почему движение не дёргается при задержке?** Свой персонаж двигается сразу (клиентское предсказание) той же функцией `moveWithCollision`, что и на сервере, и мягко подтягивается к серверной позиции. Чужих игроков мы отрисовываем на 100 мс в прошлом и интерполируем между снимками.

**Что если игрок закрыл вкладку?** Место держится 45 секунд в игре (15 в лобби). Токен сессии лежит в `sessionStorage`, и после перезагрузки клиент сам переподключается. Если таймаут истёк, игрок считается выбывшим, а при необходимости роль хоста переходит другому.

**Как защищены пароли?** scrypt со случайной солью (встроенный `node:crypto`), сравнение за постоянное время, одинаковая ошибка для неверного логина и неверного пароля, лимит попыток по IP.

**Как защищены комнаты?** Код из 6 символов (31⁶ ≈ 887 млн вариантов), строгий лимит попыток входа на сокет, в начатую игру попасть нельзя, переподключение только с секретным токеном.

**Зачем Zod, если есть TypeScript?** Типы TypeScript исчезают после компиляции, а данные из сети может прислать кто угодно. Zod проверяет их во время выполнения, а TypeScript выводит типы из тех же схем.

**Как связаны React и Phaser?** Через типизированный `GameBridge` (события `ui:*` и `game:*`) и общий `GameSession`. Они не импортируют друг друга.

**Где хранятся данные?** Временное состояние матча — в памяти сервера, это быстро. После матча итог пишется в PostgreSQL через Prisma: `Match`, `MatchParticipant`, `MatchStatistics`, профиль. Роль игрока видна только ему в его истории, публичный профиль ролей не содержит.

**Как проверяли?** Юнит-тесты на каждое правило (например, «мёртвый не голосует», «нельзя голосовать дважды», «ничья — никого не выбрасываем»), интеграционные тесты через настоящие сокеты, ручная проверка в браузере с ботами (`npm run bots`).

**Что бы улучшили?** Вентиляции и камеры, звук, мобильное управление, горизонтальное масштабирование через Redis-адаптер Socket.IO.

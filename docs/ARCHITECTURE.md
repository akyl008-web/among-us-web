# Архитектура

## Monorepo (npm workspaces)

```
among-us-web/
├─ shared/   @stellar/shared: контракт клиент ⇄ сервер (один источник истины)
│  └─ src/
│     ├─ constants.ts       лимиты, дистанции, тайминги
│     ├─ game.ts            GamePhase, Role, цвета
│     ├─ protocol.ts        RoomView (приватное представление), WorldSnapshot, настройки
│     ├─ schemas.ts         Zod-схемы ВСЕХ входящих данных
│     ├─ events.ts          типизированные события Socket.IO, коды ошибок
│     ├─ movement.ts        математика движения (клиент и сервер используют одну функцию)
│     ├─ map/               парсер Tiled, сетка коллизий, moveWithCollision
│     └─ maps/              skyward.json (Tiled) + skyward-tiles.png
├─ server/   @stellar/server: авторитетный игровой сервер
│  ├─ prisma/               schema.prisma + миграции
│  └─ src/
│     ├─ game/GameRoom.ts   машина состояний одной комнаты (чистая логика, без сети)
│     ├─ game/RoomManager.ts комнаты, сокеты ⇄ игроки, тик 20 Гц, рассылка
│     ├─ realtime/          Socket.IO: аутентификация, rate limit, обработчики событий
│     ├─ http/              Express: health, auth, профили, рейтинг, раздача клиента
│     ├─ auth/              scrypt-хеширование паролей, HMAC-токены
│     └─ db/                Persistence: Prisma (PostgreSQL) или память
├─ client/   @stellar/client: React (интерфейс) + Phaser (мир)
│  └─ src/
│     ├─ net/GameSession.ts единое хранилище клиента (сокет, состояние, снимки мира)
│     ├─ app/               экраны (меню, лобби, игра), HUD, мини-игры, собрания
│     └─ game/              Phaser: BootScene, ShipScene, спрайты, ввод, интерполяция
├─ scripts/  generate-map.mjs, bots.mjs, clean.mjs
└─ docs/
```

## Слои и границы

| Слой                 | Знает о                              | Не знает о             |
| -------------------- | ------------------------------------ | ---------------------- |
| `GameRoom` (правила) | карте, shared-типах                  | Socket.IO, Express, БД |
| `RoomManager`        | GameRoom, интерфейсе `RoomTransport` | конкретном транспорте  |
| `realtime/*`         | Socket.IO, Zod, RoomManager          | правилах игры          |
| `db/*`               | Prisma / памяти                      | игре во время матча    |
| React                | GameSession, bridge                  | Phaser                 |
| Phaser-сцены         | GameSession (чтение), bridge         | React                  |

Поэтому `GameRoom` покрыт быстрыми юнит-тестами без сети, а транспорт подменяется в тестах.

## Авторитетный сервер

Клиент отправляет только **намерения**: `player:input {up, down, left, right, seq}`, `impostor:kill {targetId}`, `meeting:vote {targetId}` и т. д. Сервер:

1. ограничивает частоту (token bucket на сокет и событие; отдельный строгий лимит на вход в комнату против перебора кодов);
2. проверяет payload через Zod (`strictObject`: лишние поля вроде `role` отклоняются);
3. проверяет права и фазу: роль, жив ли игрок, хост ли он, дистанцию, перезарядку, не голосовал ли уже;
4. меняет состояние и рассылает каждому игроку **его личное** представление (`viewFor`).

Сервер сам считает позиции 20 раз в секунду той же функцией `moveWithCollision`, что и клиент, поэтому speedhack и проход сквозь стены невозможны.

## Приватность (что получает игрок)

- Свою роль всегда. Список предателей только если ты предатель или игра закончилась.
- Смерть другого игрока видна живым только после находки тела, собрания или исключения. Призрак видит всё.
- Позиции призраков живым не отправляются (`snapshotFor`).
- Голоса во время собрания тайные: видно только, кто уже проголосовал. Распределение показывается после итогов.
- Задания у каждого свои; у предателя задания-обманки, выполнить их нельзя.

## Синхронизация движения

- **Свой игрок:** клиентское предсказание (мгновенный отклик) + мягкая коррекция к позиции сервера, телепорт при расхождении больше 80 px (собрание, убийство).
- **Чужие игроки:** интерполяция между снимками с задержкой 100 мс (`Interpolator`).
- Снимки идут только в фазе PLAYING и как `volatile`: устаревший снимок можно потерять.

## Машина состояний

`WAITING → STARTING (4 с, показ роли) → PLAYING ⇄ MEETING (обсуждение → голосование) → RESULT (6 с) → PLAYING | FINISHED → WAITING`

Победа проверяется после убийства, исключения, задания, выхода игрока и по таймеру реактора. Выходы игроков, у которых истёк таймаут, обрабатываются одной пачкой.

## Карта (Tiled)

`shared/src/maps/skyward.json` — настоящая карта Tiled (открывается в Tiled 1.10+):

- слои тайлов `floor`, `walls`, `decor`; коллизия задаётся свойством тайла `collides: true`;
- объектные слои `rooms` (прямоугольники комнат), `spawns` (точки), `interactables` (задания с `taskType`, кнопка `emergency`, точки ремонта саботажа).

Сервер и клиент разбирают **один и тот же файл** (`parseGameMap`). Тесты проверяют, что все 7 комнат на месте, точки не стоят в стенах и всё достижимо от точки появления.

## Данные (PostgreSQL + Prisma)

`User` (логин, scrypt-хеш), `PlayerProfile` (публичная статистика без ролей), `Match`, `MatchParticipant` (роль хранится здесь и видна только владельцу), `MatchStatistics`.

Временное состояние матча (позиции, голоса, текущие роли) живёт только в памяти сервера и в БД не пишется. После окончания матча записывается итог. Без `DATABASE_URL` используется хранилище в памяти с тем же интерфейсом.

## Отладка

- `npm run bots -- CODE 3 --hunt`: боты-предатели устраняют и саботируют.
- `window.__stellarGame` в dev-консоли: экземпляр Phaser.Game.
- `MIN_PLAYERS=3` в `server/.env`, чтобы стартовать втроём.
